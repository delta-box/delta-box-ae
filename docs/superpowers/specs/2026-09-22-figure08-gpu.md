# Figure 8(b)/(c) script contract

The user requests runnable scripts before allocating GPU resources. Figure 8(b) is measured GPU timing; Figure 8(c) is a CPU arithmetic model. GPU execution remains pending hardware, while planning, input validation, reference calculation and plots can be tested now.

## Measurement recipe

Follow the submitted paper and the active `plot_fig_rl_combo.py`, which loads direct timing records rather than the deprecated extrapolating plot script.

| Phase | B | GPUs | Method |
|---|---|---|---|
| Generation | 1, 4, 16, 64 | 1 | Qwen2.5-7B-Instruct, vLLM, bf16, temperature .7, top_p .95, nominal input 256, max output 512, model length 832, one warmup on up to two prompts, three repetitions |
| Training | 1, 4 | 1 | LoRA r16/alpha32 on q/k/v/o projections, bf16 base, gradient checkpointing, sequence length 768, AdamW lr 1e-4, two warmups and five repetitions |
| Training | 16, 64 | 4 | FSDP FULL_SHARD, bf16 parameters/reduction, per-GPU microbatch 4, accumulation 1/4, same LoRA/sequence/optimizer, two warmups and five repetitions |

`T_train` includes the optimizer step and distributed synchronization, as the original scripts did. Model loading and warmup remain outside timings. The original generation prompt builder produced approximately 307–308 output tokens per request because the nominal 256-token string was longer after tokenization. Preserve this default `paper-template` mode, report actual input/output counts, and expose a separate `fixed-tokens` mode for exact 256→512 inputs. Never relabel it as the same protocol.

The GPU worker imports torch/vLLM only after device selection. No CPU fallback or extrapolated large-batch timings are permitted. Invalid, failed, missing, OOM and timed-out cases do not become successful timings. Each case runs in its own process so model memory is released between inference and training.

## Public entry points

- `ae/runners/gpu_timing.py`: `plan`, `check`, `run`, `plot`. Default configuration is `ae/configs/figure08-gpu.json`; model path, devices and Python environments are supplied by CLI/config. `plan` must work without torch, CUDA or model files. `run` requires actual Linux/CUDA resources and a local model.
- `ae/runners/gpu_worker.py`: one generation or training case; called by the runner, or by single-node torchrun for FSDP.
- `ae/repro/gpu_occupation.py`: CPU-only theoretical calculation from normalized input, or a successful GPU suite plus an AE fanout analysis summary. Optional PNG/PDF output imports matplotlib lazily.
- `ae/repro/figure08_plots.py`: standalone timing/model plots. No torch import.

GPU suite JSON is `{schema_version: 1, kind: "gpu-timing-suite", status: "ok"|"failed", source_kind: "fresh", protocol: {...}, cases: [...]}`. Successful case rows contain `case_id`, `phase` (`generation` or `training`), `batch`, `num_gpus`, `method`, `status`, `timing_s` (`n`, `mean`, `median`, `p95`, `min`, `max`), and a hashed raw-result reference. Workers retain individual samples and GPU/software/model/source identities. No credentials or whole environment are dumped.

## CPU theory contract

Normalized input JSON uses `schema_version: 1`, `kind: "gpu-occupation-inputs"`, `source_kind` (`historical`, `fresh`, or `assumed`), `model_label`, `batches` (default `[16,64]`), `backends`, `gpu_timings`, `sandbox_timings`, and optional provenance/notes.

GPU rows are `{n, t_gen_s, t_train_s, generation_gpus, training_gpus, source?}`. Sandbox rows are `{backend, n, t_sandbox_s, estimated: bool, source?}`. Numeric inputs must be finite, nonnegative, with positive training time. Missing or duplicate requested inputs fail; missing sandbox time is never substituted with zero.

```python
occupation = (t_gen_s + t_train_s) / (t_sandbox_s + t_gen_s + t_train_s)
staleness_versions = (t_sandbox_s + t_gen_s) / t_train_s
```

Output kind is `gpu-occupation-model`, with rows retaining the inputs, `occupation`, `occupation_pct`, `staleness_versions`, and estimate/source annotations. This is an expected time fraction under Equation 1, not nvidia-smi utilization or a measured synchronous RL job. In particular, historical single-GPU generation and four-GPU training are not GPU-count-weighted by this formula.

Fresh fanout input is the existing AE analysis JSON: `experiments.figure-08.series` rows with `panel="a"`, `backend`, `x=N`, `y=milliseconds`, `unit="ms"`. Reject conflicting populations/duplicate points rather than silently pooling them.

`ae/configs/figure08-theory-paper.json` will preserve the original numeric inputs and hashes. Its E2B N64 value remains the historical estimate `4 * mean(two measured N16 values)`. Reference calculation and rendering are allowed without GPUs and must be labelled historical-input theory.
